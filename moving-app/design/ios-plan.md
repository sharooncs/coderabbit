# HouseMove for iPhone: plan and owner instructions

After three audit rounds (Kotlin side, Apple delivery, what the agent can verify; then technical consistency and an owner walkthrough; then a final blocker check), a spike (iOS Kotlin compiles and shared screens render on Linux) and a probe of GitHub's Xcode 27 runner. Reviewers' notes are not in the repository.

## What the agent does and verifies itself
- Linux: all Android/JVM tests, the seven-phone simulation, golden fixtures, compiling every iPhone-side Kotlin file (klib cross-compilation, proven), rendering every shared screen at 1206×2622 to PNG and looking at it (proven), Android device tests in CI.
- GitHub CI (no secrets): iOS framework link, iOS-simulator unit tests incl. golden fixtures, XCUITest flows, accessibility audit, screenshots (light/dark, largest text) pushed to a `ci-shots` branch the agent fetches, simulator↔JVM-peer sync against the released Android 2.1.1 code. iOS changes skip the Android emulator jobs.
- On the Mac via Remote Control: `tools/ios.sh setup` installs XcodeGen, a JDK 21 (Temurin) and the Android SDK (command-line tools, platform 37 and build tools 36; the Android plugin needs them even for iPhone builds) into ~/Developer/tools with curl, checksum-checked, without admin rights; the owner accepts Google's SDK licences once in Terminal (setup prints the command; nobody answers for them); ios.sh and the Xcode build step use that JDK and SDK unless JAVA_HOME or ANDROID_HOME name others; set DEVELOPER_DIR if needed; check the team and certificate names for non-ASCII letters (Xcode 27 cloud-signing bug, then an Apple Distribution certificate from Xcode → Accounts instead); generate the Xcode project (XcodeGen), build in 1–3 minutes, run the simulator, archive, sign and upload to TestFlight, install on the paired iPhone with `xcrun devicectl` and read its live log during the owner's tests.
- Cannot do: anything in the owner's Apple account in a browser, physical iPhone use (camera, printed labels, real Wi-Fi with an Android phone, look and feel), Beta App Review.

1f Internet mailbox (in the repo, branch `mailbox`; Android 2.5, versionCode 13; the iPhone still 0.1): `design/encryption.md`, "Mailbox as built", and `mailbox/README.md`. Phones of a move that are not on the same Wi-Fi keep each other up to date through a small program on the family's always-on Windows laptop, which Tailscale Funnel puts at a fixed https address. Each message is sealed on the phone for one other phone of the move (HPKE, with the phones' own keys): the laptop stores and forwards sealed bytes and can read none of it. An Organiser sets it up once by scanning the code the laptop shows; the other phones get it at their next sync. It works beside syncing on the same Wi-Fi, not instead. Update files are now sealed the same way between 2.5 phones, so the phone that opens one sees which phone sent it. The laptop's side is done by a Claude Code session there, following `design/asus-session.md`. No new Android permission (the app already has internet); nothing new for the iPhone's export answers (HPKE is a way of using CryptoKit's ECDH and AES-GCM, as Noise is).
