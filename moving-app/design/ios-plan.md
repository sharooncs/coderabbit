## What the agent does and verifies itself
- Linux: all Android/JVM tests, the seven-phone simulation, golden fixtures, compiling every iPhone-side Kotlin file (klib cross-compilation, proven), rendering every shared screen at 1206×2622 to PNG and looking at it (proven), Android device tests in CI.
- GitHub CI (no secrets): iOS framework link, iOS-simulator unit tests incl. golden fixtures, XCUITest flows, accessibility audit, screenshots (light/dark, largest text) pushed to a `ci-shots` branch the agent fetches, simulator↔JVM-peer sync against the released Android 2.1.1 code. iOS changes skip the Android emulator jobs.
- On the Mac via Remote Control: `tools/ios.sh setup` installs XcodeGen, a JDK 21 (Temurin) and the Android SDK (command-line tools, platform 37 and build tools 36; the Android plugin needs them even for iPhone builds) into ~/Developer/tools with curl, checksum-checked, without admin rights; the owner accepts Google's SDK licences once in Terminal (setup prints the command; nobody answers for them); ios.sh and the Xcode build step use that JDK and SDK unless JAVA_HOME or ANDROID_HOME name others; set DEVELOPER_DIR if needed; check the team and certificate names for non-ASCII letters (Xcode 27 cloud-signing bug, then an Apple Distribution certificate from Xcode → Accounts instead); generate the Xcode project (XcodeGen), build in 1–3 minutes, run the simulator, archive, sign and upload to TestFlight, install on the paired iPhone with `xcrun devicectl` and read its live log during the owner's tests.
- Cannot do: anything in the owner's Apple account in a browser, physical iPhone use (camera, printed labels, real Wi-Fi with an Android phone, look and feel), Beta App Review.

## Owner instructions
Never send in chat: passwords, 2FA codes, any .p8/.p12 file or its text. Fine to send: "done", Team ID, app name, Apple's emails, screenshots.

### Now (one sitting, about 30 minutes)
1. Mac: install or update Xcode 27 from the App Store, open it once, agree to the licence (asks for the Mac password) and let it install the iOS 27 platform. (Before the licence is agreed, even `git` refuses to run.)
2. Xcode → Settings → Accounts → + → Apple Account: sign in with the developer account (password and 2FA; never in chat).
3. Connect the iPhone with a cable, tap Trust. Xcode → Open Developer Tool → Device Hub → the iPhone → Pair. On the iPhone: Settings → Privacy & Security → Developer Mode → On → restart → Enable (the switch appears only once pairing has started). Pair again after each iOS update.
4. Claude desktop app on the Mac (update it first): Settings → Claude Code → Remote Control: turn it on, create the folder ~/Developer and add it, keep the Mac awake while we work. On the Windows PC, remove System32 and bin from its Remote Control list (they are not usable from here and should not be shared). Send "Mac ready"; when a card asks to let this session work on your Mac, approve it. The agent then clones the code into ~/Developer, installs XcodeGen, a JDK and the Android SDK there without admin rights, and runs `tools/ios.sh doctor`. Once, the agent asks you to paste one command into Terminal on the Mac: it shows Google's Android SDK licences; read them and type y to accept each (the iPhone build needs the Android SDK for its shared code). If the Mac's folder is listed but not offered to cloud sessions, a Claude Code session on the Mac itself does these steps instead, following `design/mac-session.md`. Stay at the Mac for the first archive a few minutes later: macOS asks once for your login password so the build can use your signing key; choose "Always Allow". If Xcode ever says the session expired, sign in again under Xcode → Settings → Accounts.
5. iPhone: install TestFlight from the App Store.

### After the agent says "bundle ID registered" (about 3 minutes in the browser)
6. developer.apple.com/account and App Store Connect → Business: accept any pending agreement (New App is blocked otherwise).
7. App Store Connect → Apps → + → New App: iOS, name "HouseMove - Moving Planner", language, bundle ID `app.housemove.ios` from the list, SKU `housemove-ios`, Full Access → Create. Name taken: tell the agent.
8. In that app: TestFlight → Internal Testing → + → name "Me" → tick "Enable automatic distribution" → Create → Invite Testers → tick yourself → Add. (There is no default group; without this no build reaches you.)
If the session can drive the Mac's browser (Claude desktop app's browser or Computer use), the agent can do 6–8 with the owner watching and signing in.

### When I say "test build uploaded" (the shell now, the shared screens at step 0e)
9. The build arrives in TestFlight automatically (your "Me" group): open TestFlight on the iPhone → Install. Nothing within 2 hours: tell me (I can install a development build directly from the Mac instead).
10. Shell check: the HouseMove icon on the home screen; the app opens to the house mark, "HouseMove" in the app's rounded font and the test build number I name. Gate G0 at step 0e: app opens; the HouseMove font shows; nothing hides under the Dynamic Island or the home bar; Home looks like the picture I send. Reply pass/fail per line.
